# v2 搜索预算修整

本版直接承接 v1。物理环境、中断类型、动作集、五目标计算和默认权重不变；修改集中在 `Env/ALNS.py`、`Env/ResultRecorder.py` 和搜索测试。

| v1 现象 | v2 处理 | 如何核对 |
| --- | --- | --- |
| 小评价预算可能先被单折返和耦合折返预试算耗尽，破坏修复迭代为 0 | 预试算最多使用除空方案外评价预算的三分之一；其余次数留给搜索和后处理 | 每轮 JSON 的 `seed_candidates_evaluated`、`iterations_completed`、`unique_candidates_evaluated` |
| 恢复期无折返候选时，退火初温固定为 1 | 无折返候选时先试算本阶段其他合法单动作，以可行正分差校准初温 | `initial_temperature`；无正分差时仍退回 1 |
| `max_seconds` 只在正式迭代中检查，预试算可持续超时 | 预试算和后处理也在启动下一次评价前检查时间 | 同一快照下对比 `search_seconds` 和预算；单次评价无法中途打断 |

上述三分之一是**搜索预算分配规则**，不是运营参数或最优比例。它解决“小预算下没有实际迭代”的失效模式；不保证两种算法的实际评价次数完全相等。正式比较仍需核对每轮实际次数与五项原始指标。

快速检查：

```powershell
python -m unittest discover -s tests -v
python run_alns.py --mode benchmark --rounds 1 --iterations 10 --max-evaluations 14 --single-scenario
```

输出仍在 `Result/alns_v1` 下，避免改动读取旧结果的脚本；目录名不是版本号。历史实验结果保留，不能把旧结果当作 v2 的运行结果。

本地验收：57 项测试通过。使用一轮、10 次迭代上限、14 次评价上限、单预测场景试跑时，LNS 与 ALNS 均实际评价 14 个不同方案，其中预试算 4 个，完成破坏修复迭代 9 次。三种模式这一轮的实际等待均为 358934 人秒，因此本试跑只证明流程与预算修正，**没有证明算法性能提升**。
