# ALNS 创新设计的下一阶段施工图（本次不改现有算法）

## 一、与本次版本的边界

本版 `Env/ALNS.py` **原样保留**，没有声称拓扑感知/车客协同/鲁棒多场景算法已经实现。用户确认：研究对象仍为单方向单区间完全封锁；列车动作仍为 Hold / Delay / Turnback / Release，乘客动作仍为 Entry Control；硬约束由原物理环境负责，一票否决；ALNS同时承担恢复方案优化器和后续可验证推理数据的候选生成器。新增五目标评分已由 `Evaluator.py` 实现，但完整OD到达延误尚未具备原始状态跟踪条件。

## 二、ALNS升级建议（后续独立版本，不在此次补丁中实现）

### 1. 拓扑感知候选生成（不增加物理动作）

从决策时 `Snapshot` 只提取已观测信息：封锁上游与下游可用折返资源、列车所在区间/下个停站、预计剩余中断时长、各站台容量饱和度 `rho=platform/capacity`。候选只包含可达、当前窗口可执行/已支持预约的动作；不允许引用实际恢复时刻、未来实际OD、真实车底未提供的交路。

新增建议的 ALNS 搜索算子（算法内部，不是新的地铁动作）：

- `destroy_related_train`：一次删除同一受阻队列/同一折返站周边的关联列车调整，而非随机删单条；
- `destroy_boundary_controls`：删除或重设与折返清客站有关的进站配额；
- `repair_topology_turnback`：优先尝试封锁上游有设施的折返站，并依 `Env` 真实检验；
- `repair_marginal_gain`：按当前预测评分的边际收益选择单个合法动作。

### 2. 车客协同修复算子

把同一方案里的列车折返与对应车站进站配额视作**组合候选**：计算清客人数、站台现有人数、预警线、预测到站需求和候选配额；先以硬容量做准入校验，再调用原 `Evaluator` 统一仿真评价。若清客后的站台已超过硬容量，即使配额设为0仍必须拒绝折返，不能靠乘客凭空转入站外队列“修好”。其余约束都由原 `Env` 判定，不复制一份新物理规则。

### 3. 鲁棒多预测场景评价

对当前可见预测生成少量预测扰动（偏短/基准/偏长恢复时间、正常/高客流），用相同动作方案在各场景下做仿真。绝不读取真实未来作为场景生成依据。优先从少量场景的加权均值或均值+CVaR开始；固定外生预测随机种子和权重用于所有候选，避免不同方案“抽到不同坏天气”。这一机制应在 `Evaluator` 的**预测数据源层**扩展，不能偷偷修改物理环境的真实历史。

### 4. 后剪枝与高质量数据

对ALNS输出的优质可行方案逐一删除动作并重跑仿真，若总综合评分恶化在**预先声明的阈值**以内、所有约束仍通过，则将该动作列为非必要。剪枝结果不等于全局最优，也不能把一次被模拟退火拒绝但仍可行的方案标为“违反安全约束”。应分别保存：

- 正样本：合规、经仿真验证、相对基础方案具有收益且解释忠实的候选；
- 难负样本：违反具体硬约束的候选及其错误代码；
- 偏好对：同一状态/预测/权重下两份均可行且评分不同的方案；
- 反事实对：仅变动一个可观测条件、引起策略变化的成对场景；
- 离线审计：存于输入/目标文本之外，不能将未来真值、事后比较成本放入决策时解释。

## 三、实现顺序与验收门槛

| 阶段 | 允许改动 | 必须先通过的验收 |
|---|---|---|
| 当前（已实现） | 五目标、只读测量、日志记录 | 41/41单元测试；CLI Rule/LNS/ALNS均能执行 |
| 下一阶段A | 仅优化ALNS候选生成和搜索算子 | 与原ALNS同一场景、权重、迭代/时间预算比较可行率、分项成本；不得降低物理约束通过率 |
| 下一阶段B | 增加车客组合修复 | 折返容量冲突测试、可行方案边际收益测试、组合算子消融 |
| 下一阶段C | 预测评价分支多场景 | 真实未来信息隔离回归；不同预测误差下均值/尾部表现和时耗 |
| 下一阶段D | 数据输出器与自动审计 | 状态真实、数值可追溯、动作可行、解释忠实、优于无解释、可复现 |

**不应提前宣称 ALNS 优于 Rule/LNS：** 本版一轮最小对照（每种搜索方法3次迭代）三者选出的实际执行结果相同。是否提升必须通过多中断位置、多时长、多客流、多随机种子和足够搜索预算的实验来证明。
