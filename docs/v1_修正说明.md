# v1 修正说明（2026-11-20）

本版基于 TPR-ALNS 增强版修改。中断仍是单个有向区间完全封锁，列车和客流动作及安全校验范围不变。五项目标仍各占 0.2；这是可运行的初值，不能解释为五项实际贡献相等或已完成偏好校准。

## 计量口径

- C2 `onboard_late_pax_sec`：车内停站、待发、扣停超过计划发车时刻的乘客人秒，加上列车处于 `RUNNING` 且等待到达下一站时，超过计划到站时刻的乘客人秒。原有车次对照原运行图，折返生成车次对照生成时冻结的新计划。它仍不是逐乘客 OD 到达延误；运行区间内其他形式的晚点不一定能分辨。
- C4 `window_schedule_adjustment_sec`：评价期内新增加的已发车时刻偏移、期末未完成到发事件的超时变化、折返取消的原方向剩余服务时长、折返新建反向服务时长，单位均为列车秒；最后取非负值。取消服务从折返站计划发车到原终点计划到站计时，新建服务从开始折返到新方向终点计划到站计时。这是**运行图改动量代理**，不代表车底周转、全部停站时刻绝对偏差或实际完成的反向服务。分项和停站数单独记录，原 `window_schedule_shift_sec` 仍保留作为旧口径对照。
- 评价窗口仍按原配置；折返导致的全程服务变更在折返动作执行的窗口一次入账，避免折返动作因评价期截断而免费。

## 搜索口径

- 初始退火温度由基础方案和可行单折返候选之间的**正分差中位数**换算，使代表性劣解初始接受概率约 50%；若没有正分差，退回温度 1。它不再依赖综合分数的绝对基线。
- `--max-evaluations N` 是每个决策轮至多 N 个不同 `ActionPlan` 的预测评价次数，包含空方案、折返种子、贪心探针和后处理。缓存命中不增加次数。标准与增强模式使用相同 N 才有同预算上界；还需在结果中的 `unique_candidates_evaluated` 核对**实际**次数是否相等。迭代数或时间提前结束时，两者实际次数仍可能不同。
- `round_*.json` 记录初温、评价预算、实际评价次数、五项权重及贡献占比，并记录所选方案与空方案的分项贡献差。鲁棒评分额外含尾部风险溢价，因此五项期望贡献之和不必等于鲁棒总分。

## 运行

```powershell
python -m unittest discover -s tests -v
python run_alns.py --mode alns --profile standard --rounds 1 --iterations 200 --max-evaluations 30 --single-scenario
python run_alns.py --mode alns --profile enhanced --rounds 1 --iterations 200 --max-evaluations 30 --single-scenario
```

上述两条命令用于同预算搜索检查；正式对照仍需固定场景、种子、权重和鲁棒设置，核对实际评价次数及原始五项指标。若某模式在达到 30 次前结束，不能宣称已完成严格等评价次数比较。
